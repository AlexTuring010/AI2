## Χρόνος εκτέλεσης — το #1 πρόβλημα όλων
- Και τα 3 μοντέλα σε 1 notebook **αργούν τρομερά**. Αναφορές για 5–10+ ώρες συνολικά.
- 0.8B μόνο του: ~4 ώρες στο Kaggle για κάποιους. Σε RTX 4080 τοπικά ~90 λεπτά για όλα.
- Κάποιος περίμενε ~7 ώρες απλά για να *ξεκινήσει* το 4B.
- Με tweaks ο χρόνος πέφτει αλλά μέχρι ~4ωρο για το πρώτο μοντέλο — **δεν βρέθηκε κάποιο
  "magic" optimization**.
- Συμπέρασμα: ο χρόνος είναι ο κύριος εχθρός. Πρέπει να σχεδιάσουμε γύρω από αυτό
  (subset, batching, σωστό `max_new_tokens`, ίσως διαχωρισμός πειραμάτων από το τελικό run).

## Qwen "thinking mode" — κρίσιμη παγίδα
- Τα Qwen3.5 έχουν εσωτερικό **thinking mode** που καίει output tokens (2–3k+ tokens,
  ειδικά σε CoT· κάποιος ανέφερε ~5 λεπτά για ένα μόνο prompt στο μικρό μοντέλο).
- Υπάρχει παράμετρος **`enable_thinking=False`** — αλλά κάποιος είπε ότι όταν το κλείνει
  "τα χαλάει όλα". Θέλει κατανόηση/πειραματισμό, όχι τυφλό κλείσιμο.
- Σχετικές παράμετροι που αναφέρθηκαν: `max_new_tokens` (πρέπει να καλιμπραριστεί),
  `do_sample`.

## OOM / μνήμη
- Πολύ συχνά **OOM στο Kaggle**. Πολλοί κατέληξαν αναγκαστικά σε `batch_size=1`.
- batch 2–4 δουλεύει για κάποιους, 8+ → OOM.
- Few-shot με πολλά παραδείγματα → OOM (κάποιος είπε ότι το "βέλτιστο" κατά τα docs είναι
  ~27 examples αλλά δεν σηκώνεται στη μνήμη).
- **Clear μνήμης / cache μετά από κάθε μοντέλο** βοηθάει.
- Το OOM εμφανίζεται συχνά από **Qwen3.5-4B + few-shot** και μετά.
- Colab Pro με A100 τρέχει άνετα ενώ το Kaggle βγάζει OOM στα ίδια πράγματα.

## Kaggle: όρια GPU & sessions
- Εβδομαδιαίο όριο GPU **~30 ώρες**, reset Παρασκευή βράδυ / ξημερώματα Σαββάτου
  (ανεξάρτητα από το πότε ξεκίνησες να το χρησιμοποιείς).
- Όριο ανά execution ~9–12 ώρες.
- **Δεν επιτρέπεται** απευθείας submit του csv ως file upload — πρέπει να παραχθεί από
  το notebook.
- Αν δεν φτάνουν οι ώρες, κάποιοι σκέφτονται 2ο account (ρίσκο, και πρέπει να μεταφερθούν
  όλα στο βαθμολογούμενο notebook).

## Σκορ — ρεαλιστικές προσδοκίες
- zero-shot / few-shot F1 γενικά **κάτω από 0.40–0.42**. Συγκεκριμένες αναφορές:
  leaderboard ~0.27, τοπικά ~0.34, κάποιος ~0.42.
- Καλύτερο μοντέλο: ασαφές — κάποιος είπε ότι του βγήκε καλύτερα το 2B (αλλά "όχι καλό").
- Δηλαδή το task είναι όντως δύσκολο με σκέτο prompting· το ζητούμενο είναι η **ανάλυση**,
  όχι το ψηλό σκορ.

## Συμπεριφορά 4B
- Κάποιοι: το 4B σαν να **αγνοεί τα prompts**, δεν επιστρέφει καθαρή κατηγορία.
- Λύση που χρησιμοποιήθηκε: **fallback στην πιο συχνή κατηγορία** για τα invalid outputs.
- Πιθανή αιτία (υποψία φοιτητή): λάθος τρόπος φόρτωσης του μοντέλου.

## Prompt design
- Τα prompting techniques μπαίνουν **και στο user prompt**, όχι μόνο στο system prompt
  (το είπε η υπεύθυνη στο φροντιστήριο, μεταφέρθηκε στο Discord).
- Διαβάστε το **model card** κάθε μοντέλου (σελίδα HF) — περιγράφει optimal prompts/ρυθμίσεις.
- Πολύ υλικό στο prompting guide που προτείνει η εκφώνηση.
